# Paint W5a engine and debug fixture

Issue #53 W5a adds a local Canvas 2D engine and an isolated Vite debug page at `/paint-debug.html`. Start it from `apps/web` with `pnpm exec vite --config paint-debug.vite.config.ts`. It does not register a Paint module, touch shared document schemas, import remote images, or save to a site. W5b and W5c remain separate.

The source bitmap is always at logical resolution. The display canvas is redrawn from it at up to 2× device pixel ratio and CSS zoom changes only display size. PNG encoding uses the source bitmap, so output dimensions and alpha do not depend on zoom or DPR. The pointer controller captures one primary mouse, pen, or touch pointer, treats each gesture as one history transaction, and restores its initial pixels on `pointercancel` or lost capture. Pointer moves draw imperatively; they do not update React or DOM nodes.

Limits: default 640×480; integer width 1–1024 and height 1–768, with no more than 786,432 logical pixels; zoom 0.5–4; effective DPR at most 2; at most eight RGBA undo/redo snapshots total. At the maximum size, each `ImageData.data.byteLength` is 3,145,728 bytes. Eight snapshots retain at most 25,165,824 bytes. The logical bitmap and 2× display backing store account for another 15,728,640 bytes; one active gesture snapshot adds 3,145,728 bytes. The directly managed RGBA budget is therefore at most 44,040,192 bytes (42 MiB), excluding browser encoder buffers, canvas implementation overhead, and page memory. This is an allocation bound, not a device speed or total process memory claim. The browser test measures `ImageData` and backing dimensions at the maximum size.

The fixture confirms before clearing or replacing an unsaved canvas. Clear is undoable; New starts a blank canvas with empty history. Export downloads a local transparent PNG. The fixture exposes `window.paintDebug.engine` for browser pixel tests only. No Apple Pencil hardware claim follows from simulated touch tests.
