## Recommended smallest usable slice

Choose **R1 (no persisted shape changes)** first, then R2 reader + gated writer. A schema-first all-module rollout would collide with W3b and expand compatibility risk; a new URL-only picker would leave the broken entity-session path unresolved.

### R1 — existing data, working shared picker and session navigation

1. Extract a shared searchable `LinkTargetPicker` with URL/window/OC/post catalog entries and local pending selection. Links inline + Inspector use only their functioning URL/window subset and write their existing fields. Explorer consumes the same picker for its existing entity references. Do not show music, embed or unsupported action options. Apply is one existing author update; Cancel writes nothing. Keep icon, label and color controls independent.
2. Adapt legacy LinkAction and Explorer refs into one **in-memory** destination union. Internal destination shape reuses `Pick<EntityRef,"siteId"|"id"|"kind">` narrowed to window/profile/post. URL shape is `{kind:"url",url,presentation:"external"}`. Do not create competing flat profileId/windowId contracts. Resolve against an authoritative scoped source catalog; unknown directory is not an empty directory. A sample can use local window IDs but cannot fabricate entity/site ownership.
3. `resolveLinkDestination` is pure and returns a typed result; `dispatchUiActions` has an explicit allowlist and shell capabilities. First supported operation is opening one destination (window/profile/post or existing external URL). Editing calls fail inertly. No author-store/API dependency, auto playback, trigger-on-open, arbitrary code, delay or recursion.
4. Desktop: reuse exact-profile IG host, then another suitable IG host, else create one temporary viewer; open/restore/focus it. Post resolution selects the post's actual author. Mobile: same resolver, one active app, a local return frame to the triggering app/control (ordinary home-icon open still returns home). Stop outgoing media using existing helpers.
5. Send an incrementing session request ID to IG. Consume each validated request atomically as a profile/post route, including repeated activation of the same target; keep IG's route/back/scroll behavior. Do not rewrite entry `profileRef`, `defaultOpen`, layout or `onProfileSelect`. Existing preview source changes revalidate/drop ineligible routes; desktop/mobile swaps preserve valid session position and still stop media.
6. Existing external URLs remain external; internal activation must not use full-page navigation or browser history. Direct shared deep links remain supported. Real buttons supply click/Enter/Space activation and return focus. Public failures use a generic localized unavailable message, with no hidden identity details.

## R2 — shared persisted reader contract, then writer

**Proposed contract to ratify once:** `LinkDestination` uses the same narrowed EntityRef shape; `UiAction` uses `{kind:"openDestination",destination:LinkDestination}` first. Keep existing `LinkAction` as an adapter, not a second stored contract. R1's in-memory destination type becomes a re-export of the shared type in R2; do not retain two definitions. Reserve additional action kinds for their tested shell capabilities. A future sequence uses strict known kinds, at most five steps, stops on first failure, prevents re-entrant same-tick dispatch and never adds loop/delay/expression semantics. R1 exposes only one action; no disabled or fake sequence/Dialog controls.

First stored carrier: optional `destination` on a Links item in canonical v2. Absence derives existing target/url/windowId unchanged. Presence is authoritative; the writer clears legacy destination slots to neutral values instead of dual-writing a misleading fallback. Preserve label/icon/color. No new defaults or empty destination objects. Document/gallery/about/IG/image carriers and Dialog/audio actions come after this carrier is verified end to end.
