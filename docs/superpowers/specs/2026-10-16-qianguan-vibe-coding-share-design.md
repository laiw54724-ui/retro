# 牽關開發分享與 Vibe Coding 教學設計

日期：2026-10-16

## 目標

把現有 Canva 簡報整理成一份適合自行滑閱的圖文分享。主角是「牽關」的開發故事，Retro Desktop 是後半段的開源教學案例。讀者包含完全沒寫過程式的創作者，以及略懂 HTML 或 GitHub、想開始用 AI 做專案的人。

同時提供一份較詳細的 Markdown 文件，收錄可複製的指令、驗收清單和進階 staging 範例。簡報負責讓讀者理解方法與產生興趣，文件負責讓讀者實際操作。

## 核心原則

1. 保留現有第 1–5 頁的牽關故事、個人口吻與視覺結構，只調整明顯錯字、換行、頁碼與必要的銜接文字。
2. 不把牽關和 Retro Desktop 寫成同一個專案。新增明確轉場，說明 Retro Desktop 是用來拆解流程的開源教學案例。
3. 不追求極少頁數。正式圖文可擴成約 28–32 頁，讓每頁只承擔一個主要概念，適合手機閱讀。
4. 沿用灰底、深咖啡、黃綠、白色，以及「被被子 / CREATOR NOTES」的現有視覺語言。
5. Git、Issue、PR、安全與部署概念可以留在簡報，但完整指令、技術細節和長篇案例移入 Markdown 文件。
6. 不聲稱未實際驗證的功能、測試或部署結果。Retro Desktop 的狀態以提供的進度紀錄與目前 repository 為準。

## Canva 編輯策略

1. 先複製現有 Canva 設計，原稿保持不變。
2. 在副本中保留第 1–5 頁的排版與個人口吻。
3. 以既有版型拆分第 6 頁之後的內容，不另外套用陌生模板。
4. 更新所有正式頁碼與章節標示。
5. 優先使用作者自己的牽關、Retro Desktop、GitHub 與工具截圖。缺圖處保留清楚的可替換佔位，不擅自使用他人作品。
6. 檢查目前第 24 頁是否為暫存或誤貼內容。在副本中只保留經確認的正式附錄，不直接刪改原稿。
7. 完成草稿後先提供 Canva 預覽，取得使用者明確同意才儲存正式修改。

## 文字與版面標準

- 每頁只設定一個主要訊息。
- 標題直接說明本頁主題，不使用空泛口號。
- 保留作者自然、帶表情的口吻，但技術說明使用短句。
- 手機縮圖仍需看得清楚主要標題和核心句。
- 長 Prompt 不放在投影片，改用短版範例與詳細文件連結。
- 不把「AI 說完成」寫成已驗收；未測試的項目明確標示未驗證。

## 驗收標準

### 簡報

- 前五頁的故事與風格仍可辨識為原稿。
- 讀者能清楚分辨牽關與 Retro Desktop。
- 讀者能理解 GPT Chat、Design 工具與本地 AI 的分工。
- 每頁在手機尺寸下可閱讀，沒有明顯溢出或過小文字。
- 正式頁碼、章節標示、附錄與來源一致。
- 沒有秘密、私人資料或未授權素材。

### Markdown 文件

- 新手可依文件完成一個小型網站任務的描述與驗收。
- 每個 Prompt 都包含目標、範圍、禁止事項與完成標準。
- staging 範例明確禁止 production 操作與秘密外洩。
- 牽關故事、Retro Desktop 現況與通用教學清楚分開。
- 沒有未完成的佔位文字或真假難辨的完成宣稱。
