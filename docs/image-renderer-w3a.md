# Image renderer foundation (Issue #51 W3a)

`ImagePresentation` in `apps/web/src/features/modules/image/presentation` renders an image source with alt text, an optional caption, contain/cover/original fit, the existing `ImageCrop` position and zoom values, a transparent/checker/color backing, pixelated rendering, and an optional simple frame. It resolves protected asset references through the existing `assetSource` hook and delegates image loading to `SafeImg`. The source is not rewritten or recompressed. There is no production module registration or document integration in W3a.

The stage measures its CSS pixel dimensions with `ResizeObserver`. `imagePlacement` computes pixel geometry from the decoded image's natural dimensions. A display edge is capped at 32,768 CSS pixels to bound layout for extreme aspect ratios; for those cases, cover may no longer fill the stage. This cap does not limit source bytes or decoding memory. Invalid natural or stage dimensions yield no placement until valid measurements arrive.

In visitor mode, decorative images have empty alt text, no caption or tab stop, and pass pointer input through to content beneath. In editor mode, the selection overlay is a real button if `onSelect` is supplied. This layer only presents and selects an image; it does not upload, save, publish, or expose a pretend GIF pause command. Style changes keep the same `<img>` node so an animated GIF continues normally.

Run the dedicated `apps/web/image-w3a-debug.html` fixture with `apps/web/image-w3a.vite.config.ts`. Its synthetic PNG, WebP and GIF files live in `tests/fixtures/image-w3a`, outside the production public directory. The fixture also exercises composition inside the existing `WindowChrome`. The browser spec lives in `tests/image-w3a`, outside the default Playwright `tests/e2e` discovery path, because only its dedicated Vite config serves those synthetic files. Browser tests use local assets and intercept synthetic protected asset requests; they do not require a site or account. A failed image retries if the source changes away and back.

Validation from base main `79e19c0f692334ef81fbe876c9b9fc7e78462c7f`: web TypeScript/lint passed; three placement unit tests and five focused Chromium fixture tests passed. Chromium uses isolated port 5212 and `test-results/image-w3a`. The browser checks actual rendered fit and transparency pixels, extreme aspect ratios, narrow widths, GIF element identity, decoration pointer-through, selection, error retry, and late protected asset results. The suite does not claim native device or browser coverage.

The default `playwright.config.ts --list` discovers 477 tests in 50 files and excludes this synthetic fixture suite. `playwright.image-w3a.config.ts --list` discovers its five tests in one file; all five pass against the dedicated Vite config. This keeps the normal site gate from requesting fixture images that its Vite config does not serve.

W3b/W3c remain pending: schema and editor wiring, upload flow, persisted behavior, and visitor integration must be completed separately before this is a production image module.
